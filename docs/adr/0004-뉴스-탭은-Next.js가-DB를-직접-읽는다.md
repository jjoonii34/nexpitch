# ADR 0004 — 뉴스 탭은 Next.js가 Neon을 직접 읽는다

- 날짜: 2026-11-14
- 상태: 승인

## 배경
수집 배치가 기사를 Neon에 쌓기 시작했다(ADR 0003). 뉴스 탭이 이 기사를 읽어 보여줘야 한다. 뉴스 탭은 읽기만 한다 (구단 선택, 단어 검색).

## 선택지
1. **Next.js 서버 컴포넌트가 Neon을 직접 읽는다** — 서버가 늘지 않고 배포는 Vercel 한 곳 그대로.
2. FastAPI를 만들어 배포하고 Next.js가 그 API를 호출한다 — 확정 스택대로지만 백엔드 호스팅 결정이 먼저 필요하고, 무료 서버는 잠들었다 깨느라 첫 화면이 느릴 수 있다.

## 결정
1번. 경기 화면이 외부 API를 직접 읽는 것(ADR 0002)과 같은 방식이다.

## 결과
- 라이브러리: `@neondatabase/serverless`(Neon이 만든 드라이버, MIT). 요청마다 잠깐 떴다 사라지는 Vercel 함수에서도 연결을 오래 붙잡지 않고 HTTPS로 조회한다. 버린 대안: `pg`(연결을 유지하는 방식이라 서버리스에서 연결 수 관리가 필요).
- 읽기는 `frontend/lib/news.ts` 한 곳에서만 한다. 화면은 `getClubs`·`getNews`만 부른다. 결과는 5분 캐시한다(기사는 하루 2회만 들어온다).
- 쓰기는 계속 `backend/`의 배치만 한다. 테이블 정의의 원본은 `backend/app/models/news.py`이고, 프론트의 SQL은 그 모양에 맞춰 쓴다 → **테이블을 바꾸면 두 곳을 함께 고쳐야 한다.**
- `DATABASE_URL`을 Vercel 환경변수에도 넣어야 한다. 없으면 샘플 뉴스와 안내 띠가 보인다.
- **확인 필요 / 남은 위험**: 프론트가 쓰는 주소는 쓰기 권한까지 있는 계정이다. 서버에서만 쓰이므로 브라우저에 노출되지는 않지만, 읽기 전용 계정을 따로 만드는 것이 더 안전하다 → 나중에 처리.
- 글쓰기 기능(팔로잉 저장, 반응 버튼)이 생기면 FastAPI 도입과 함께 이 ADR을 다시 연다.
