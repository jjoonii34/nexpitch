# ADR 0007 — 경기 분석 데이터는 API-Football 무료 플랜에서 모아 DB에 쌓는다

- 날짜: 2026-11-16
- 상태: 승인 (2026-11-16)

## 배경
v1의 중심이 "경기 데이터 분석"으로 바뀌었다(notes 2026-11-16). 20개 구단의 경기별 라인업·이벤트·스탯이 필요한데 football-data.org 무료 플랜에는 없다(ADR 0001). 가디언 건(ADR 0006)의 교훈대로 **약관 확인 → 저장 범위 결정 → 수집** 순서로 간다.

## 약관 (2026-11-16, 소유자가 대시보드에서 확인한 요약)
- 계정 1인 1개, 무료 혜택을 늘리기 위한 다중 계정 금지, 요금제별 호출 한도 준수 (무료: 하루 100회·분당 10회 — 응답 헤더로 확인).
- 로고·엠블럼·선수 이미지는 식별 목적으로만. 상업적 활용(베팅·중계·미디어)은 리그·협회 라이선스 책임이 사용자에게 있음. **원본 데이터를 가공 없이 재판매 금지.**
- 데이터 저장·가공·ML 입력을 **금지하는 조항은 없다.** 우리 용도(비상업, 저장 후 통계·LLM으로 가공해 자체 분석 표시)는 재판매가 아니다.
- **확인 필요**: 위는 요약본이다. 원문(영어) 링크를 이 ADR에 추가하고, "store/cache" 관련 조항이 원문에 따로 있는지 한 번 더 본다. 선수 이미지는 쓰지 않는다(식별 목적 조항 회피).

## 선택지
### 데이터 소스
1. **API-Football 무료** — 2022~2024 시즌 지난 경기도 id로 라인업·이벤트·팀 스탯(xG)·선수 스탯·부상이 온다(2026-11-16 호출 12회로 확인). 현재 시즌은 어제~내일 3일 창만. 하루 100회.
2. 유료 데이터(Opta/StatsBomb 등) — 비용 0원 원칙 위반.
3. 공개 데이터셋(StatsBomb Open Data 등) — 과거 일부 대회만, 현재 시즌 없음. 연구용 보조로는 가치 있음(백로그).

### 수집 범위 (소유자 결정 2026-11-16: "가")
- 경기당 3회: **라인업 + 팀 스탯 + 선수 스탯**. 이벤트(분 단위)는 나중에 추가.
- 순서: 2024 시즌(380경기) → 현재 시즌(3일 창 안에서 매 경기) → 2023 → 2022. 하루 약 90회 → 2024 시즌 약 13일, 3시즌 약 38일.

### 원본 응답을 어디에 두나
1. **DB의 JSONB 테이블(`raw_responses`)** — Actions 컴퓨터는 매번 새것이라 `data/raw/` 파일이 남지 않는다. DB에 두면 호출을 다시 하지 않고 파싱만 다시 할 수 있다(4-1 "원본 저장" 규칙). 용량 추산 1,140경기 × 3 × 약 30KB ≈ 100MB (Neon 무료 한도 확인 필요).
2. 파일(`data/raw/`) — 내 컴퓨터에서만 유효. Actions와 맞지 않는다.

### 테이블 모양
1. **정규화 (추천)** — `teams`(API id ↔ 우리 `clubs` 연결), `players`, `fixtures`(경기·결과), `lineups`(경기·팀·포메이션·감독), `lineup_players`(선발/벤치·위치), `team_match_stats`(슛·점유율·xG…), `player_match_stats`(출전 분·평점·패스…), `raw_responses`. 분석 쿼리(선발 변화, 특성 만들기)가 SQL로 바로 된다.
2. JSONB만 두고 필요할 때 꺼내 쓰기 — 시작은 빠르지만 분석 단계마다 JSON을 뒤져야 하고 테스트가 어렵다.
3. 넓은 한 테이블 — 선수별·팀별 스탯이 섞여 금방 깨진다.

### 구단 연결
- `clubs`에 열을 추가하려면 ALTER TABLE(첫 스키마 변경 → Alembic 도입 시점)이다. 대신 **새 테이블 `teams`(api_football_id, name, club_id)**로 연결하면 `create_all`만으로 되고, 20개 구단 밖의 팀(강등·과거 시즌 팀)도 담을 수 있다. 추천.

## 결정
소스 1, 범위 "가", 원본은 DB JSONB, 테이블은 정규화, 구단 연결은 `teams` 테이블.

## 결과
- `backend/app/collectors/api_football.py`: 엔드포인트별 `fetch`(원본 저장) + 순수 `parse_*`. 분당 10회 한도 → 호출 사이 7초.
- `backend/app/analysis_collect.py`: "아직 없는 것부터" 하루 약 90회. 별도 Actions 워크플로(`analysis-batch.yml`, 매일 1회). Secret `API_FOOTBALL_KEY` 필요.
- 첫 실행(2026-11-16)에서 Neon이 호출 사이 7초 쉬는 동안 연결을 끊어 실패 → `pool_pre_ping` + 팀·선수 미리 읽기(왕복 절감)로 해결. 시즌 3개 경기 목록 1,140건은 요청 3회로 들어왔다.
- 키는 `backend/.env`로 옮겼다(프론트 `.env.local`에도 남아 있음 — 프론트는 쓰지 않으므로 지워도 됨).
- 라인업·이벤트가 보이는 "경기 상세 라인업"은 **이 데이터로 되살릴 수 있다**(roadmap 보류 항목). 단, 현재 시즌은 3일 창 안에 수집된 경기만.
- Neon 무료 용량과 API-Football 원문 약관은 확인 후 이 ADR을 갱신한다.
