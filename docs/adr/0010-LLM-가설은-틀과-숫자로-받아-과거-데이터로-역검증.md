# ADR 0010 — LLM 가설은 '틀 + 숫자'로 받아 과거 데이터로 역검증한다

- 날짜: 2026-11-18
- 상태: 승인

## 배경
3단계(ADR 0009)의 프롬프트 v1은 가설을 자유 문장으로 받았다. 실제 답은 "점유율을 60% 이상 유지하며 승리한다", "수비적으로 나설 경우 실점 확률이 증가한다"처럼 **우리 데이터로 셀 수 없는 말**이었다. 컨셉은 "가설은 LLM, 검증은 통계"(CLAUDE.md 4-4)인데 검증할 수 없으면 그럴듯한 문장일 뿐이다.

## 선택지
1. **가설을 틀로 강제 (채택)** — `<특성> <>=|<=> <값> 이면 홈 승률이 <높다|낮다>`. 특성은 특성 표의 5개 열 중에서만. pydantic 스키마(Literal)로 API가 강제한다. 과거 경기에서 바로 셀 수 있다.
2. 자유 문장을 다른 LLM 호출로 조건식으로 번역 — 호출이 두 배, 번역이 틀리면 엉뚱한 것을 검증한다.
3. 사람이 가설을 읽고 손으로 검증 — 380경기에 불가능.

### 판정 방법
1. **두 집단 홈 승률 차 + 부트스트랩 95% 구간 + 최소 표본 (채택)** — 조건 성립 경기와 나머지의 홈 승률 차. 구간이 전부 주장 방향이면 `supported`, 아니면 `not_supported`, 어느 쪽이든 20경기 미만이면 `insufficient`. 효과 크기·구간·표본 수를 같이 보여준다.
2. p값만 — 효과 크기가 안 보이고 설명이 어렵다.

검증 데이터는 **학습 시즌(2022·2023, 760경기)만** 쓴다. 가설이 나온 평가 시즌 경기는 넣지 않는다.

## 결정
위 채택안. 코드: `llm_analyst.py`의 `Hypothesis`·`ask_v2`(프롬프트 버전 `v2`), `backtest.py`(순수 함수), `backtest_run.py`(`predictions.hypothesis_json` → `hypothesis_checks`). 테스트는 규칙을 심은 가짜 표로 세 판정을 확인한다.

## 결과 (2026-11-18, 2024 시즌에서 고르게 뽑은 100경기 중 97경기 — 3건은 Gemini 503)

| 판정 | 건수 |
|---|---|
| 근거 있음 | 83 |
| 표본 부족 | 12 |
| 근거 없음 | 2 |

**이 숫자를 "LLM 가설의 86%가 맞았다"로 읽으면 안 된다.** 97건 전부가 `elo_diff` 하나만 썼고(서로 다른 가설은 21개), 내용은 "Elo 차가 크면 홈 승률이 높다"는 **당연한 말**이다. 예: `elo_diff >= 200` → 조건 56경기 홈 승률 80% vs 나머지 45% (차 +36%p, 구간 +24~+46).
- 검증 장치는 의도대로 동작했다: 근거 없음 2건은 LLM이 방향을 거꾸로 쓴 것(`elo_diff <= -100이면 홈 승률이 높다` → 실제 차 −34%p)을 잡았고, 표본 부족 12건은 극단 조건(`>= 300`은 8경기)이었다.
- **가설 생성기로서의 LLM은 아직 쓸모를 보이지 못했다.** 원인 추정: ① 입력에서 Elo 차가 가장 두드러진 숫자이고 xG·선발 변경은 대부분 "not available" ② 프롬프트가 "당연하지 않은 가설"을 요구하지 않는다 ③ 고를 수 있는 특성이 5개뿐이다.
- 다음: 4.5단계 전술 특성으로 재료를 늘리고, 프롬프트 v3에서 Elo 단독 가설을 금지·경기마다 다른 특성을 요구한다. 같은 가설을 여러 번 검증하면 우연히 통과하는 것이 생기므로(다중 비교) 서로 다른 가설 단위로 센다.

**틀릴 수 있는 것**: 학습 시즌의 xG·선발 변경은 0% 채워져 있어 그 특성 가설은 지금 나와도 전부 '표본 부족'이 된다. 부트스트랩은 경기들이 서로 독립이라고 가정한다(같은 팀의 연속 경기는 완전히 독립이 아니다).
