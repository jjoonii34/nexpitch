# ADR 0003 — 뉴스 저장소로 Neon(무료 호스팅 PostgreSQL) 채택

- 날짜: 2026-11-14
- 상태: 승인

## 배경
수집한 기사를 쌓아 둘 곳이 필요하다. DB 종류는 PostgreSQL로 이미 확정이고, 정할 것은 "어디에 두느냐"다. 수집은 GitHub Actions가 하루 2회 돌리므로(상주 서버 없음) 배치가 끝나도 데이터가 남아야 하고, Vercel의 뉴스 탭이 읽을 수 있어야 한다. 비용 0원.

## 선택지
1. **무료 호스팅 PostgreSQL (Neon)** — 배치와 Vercel이 둘 다 인터넷으로 접속한다. 순수 PostgreSQL만 제공해 설명이 단순하다.
2. Supabase — 같은 무료 호스팅이지만 인증·스토리지 등이 함께 딸려 오고, 오래 안 쓰면 프로젝트가 정지되는 것으로 알고 있다.
3. 내 컴퓨터의 PostgreSQL(Docker) — 가입 없이 시작하지만 배포된 앱과 배치가 접속할 수 없다.
4. SQLite 파일 — 가장 단순하지만 배치가 끝나면 파일이 사라지고 Vercel에서 읽기 어렵다.

## 결정
1번. 접속 주소는 `backend/.env`의 `DATABASE_URL`에 둔다.

## 결과
- 라이브러리: SQLAlchemy(Python 코드로 테이블 정의·읽기·쓰기), psycopg(PostgreSQL 접속 드라이버).
- 테이블 3개: `clubs`(구단·가디언 태그), `articles`(기사, `url` 중복 금지), `article_clubs`(기사 ↔ 구단, 여러 대 여러).
- 테스트는 메모리 안의 SQLite로 돌린다 (네트워크·가입 없이 실행). 그래서 저장 코드는 PostgreSQL 전용 문법을 쓰지 않는다.
- 테이블 변경 관리 도구(Alembic)는 아직 넣지 않는다. 스키마를 처음 고칠 일이 생기면 추가한다.
- **확인 필요**: Neon 무료 한도(용량, 미사용 시 잠드는 조건) — 가입 화면에서 확인. 잠든 DB는 첫 접속이 몇 초 느릴 수 있다.
- 경기 데이터(football-data.org)는 계속 프론트가 직접 호출한다. 이 ADR은 뉴스 저장만 다룬다.
