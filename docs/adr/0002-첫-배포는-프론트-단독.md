# ADR 0002 — 첫 배포는 Next.js 단독, 백엔드 없이

- 날짜: 2026-11-14
- 상태: 승인

## 배경
확정 스택은 FastAPI + PostgreSQL 백엔드와 Next.js 프론트다. 하지만 경기·순위 화면은 저장할 데이터가 없고 외부 API를 읽어 보여주기만 한다.

## 선택지
1. **Next.js 서버 컴포넌트가 football-data.org를 직접 호출** — 서버 1개, 배포 1곳(Vercel).
2. FastAPI를 먼저 만들고 프론트가 그걸 호출 — 백엔드 호스팅 결정(별도 ADR)이 선행돼야 함.

## 결정
1번으로 먼저 배포한다. API 키는 서버에서만 쓰이므로 브라우저에 노출되지 않는다.

## 결과
- 뉴스 수집·LLM 요약·기자 티어처럼 **저장이 필요한 기능**부터 FastAPI/PostgreSQL을 도입한다. 그때 경기 데이터 호출을 백엔드로 옮길지 다시 정한다.
- Next.js 16의 Cache Components 방식 사용: 데이터 호출 함수에 `use cache`, 화면은 `<Suspense>`로 감싸 요청 시점에 채운다.
- 배포: GitHub 레포 → Vercel Import (Root Directory = `frontend`).
