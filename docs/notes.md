## 2026-11-14 — 프론트 뼈대 + 경기 탭 + 리그 탭

**무엇을 왜**
- 가장 빨리 "배포된 결과물"을 보려고 Next.js만으로 경기·순위 화면부터 만들었다. 저장할 데이터가 없어서 백엔드는 아직 필요 없다 (ADR 0002).
- 데이터는 football-data.org에서 온다 (ADR 0001). 흐름: `football.ts`(호출·캐시) → `mappers.ts`(우리 타입으로 변환) → 화면 컴포넌트. 화면은 외부 API 모양을 모른다 → API를 바꿔도 화면은 그대로.
- 한국 날짜 하루는 UTC로 이틀에 걸친다. 그래서 전날~당일을 조회하고 한국 날짜로 걸러낸다.
- 키가 없거나 호출이 실패하면 샘플 데이터를 보여주되 "샘플 데이터입니다" 띠를 반드시 띄운다 (가짜를 진짜처럼 보이지 않게).
- 테스트는 변환기·날짜 계산에만 붙였다. Node 내장 테스트 러너를 써서 라이브러리 추가가 없다 (`npm test`, 5개 통과).

**틀릴 수 있는 것**
- 실제 API 응답으로는 아직 검증하지 못했다 (키 없음). 필드 이름은 v4 문서 기억에 의존 → 키 연결 후 확인 필요.
- 무료 한도·도움(assists) 제공 여부 확인 필요.

**비용**: 0원. football-data.org 무료 키, Vercel Hobby.

## 2026-11-14 — 첫 배포 (Vercel)

- GitHub 레포를 Vercel에 연결해 https://nexpitch.vercel.app 으로 배포했다. 이후 `git push`만 하면 자동으로 다시 배포된다.
- 막혔던 점 1: 배포는 Ready인데 404. Next.js 앱이 레포 맨 위가 아니라 `frontend/`에 있는데 Root Directory를 지정하지 않아, Vercel이 레포 전체를 정적 파일로 올렸다. `/frontend/package.json`이 열리는 것으로 확인했고, 프로젝트를 다시 Import하며 Root Directory를 `frontend`로 지정해 해결.
- 막혔던 점 2: 배포 후 샘플 데이터 표시. `.env.local`은 git에 올라가지 않으므로 Vercel 환경변수에 키를 따로 넣어야 하고, 환경변수는 Redeploy해야 반영된다. 정확한 실패 원인은 끝내 확인하지 못했다(키 재입력 후 해결됨. 호출 한도 초과였을 가능성도 있음).
- 그래서 고친 것: 캐시 함수(`use cache`) 안에서 던진 오류는 배포 환경에서 내용이 가려진다. 실패를 값으로 돌려주도록 바꿔 화면에 원인(키 형식, 응답 코드)이 나오게 했다.
